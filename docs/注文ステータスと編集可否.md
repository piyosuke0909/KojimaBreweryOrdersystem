# 注文ステータスと編集可否

2026-10-22の追加要望により、注文の状態を次の3つに統一しました。

| ステータス | 注文編集 | キャンセル |
| --- | --- | --- |
| 受付済 | 可 | 可 |
| 発送済 | 不可 | 不可 |
| キャンセル済 | 不可 | 不可 |

受付済でも、請求書発行済み、別の担当者が編集中、顧客の変更・キャンセル期限後の場合は操作を制限します。可否とその理由を注文詳細に表示します。既存の請求書・金額履歴・締切ルールを保持しています。

管理者は「注文管理 → 注文詳細 → 注文の操作」でステータスを選び、確認後に変更します。受付済から発送済にすると、管理者も注文内容の編集・キャンセルができなくなります。誤って発送済にした場合は、実際の発送状況を確認して受付済へ訂正できます。訂正は履歴に残り、請求ロックを解除しません。

キャンセル済への変更には、従来のキャンセル確認と管理者の理由入力を使います。キャンセル済の注文を受付済・発送済へ戻すことはできません。顧客側ではキャンセル理由を求めません。

以前の確認済・配送準備中は受付済、完了は発送済として、一覧・検索・ダッシュボード・注文詳細に表示します。保存済みの注文や監査履歴を一括で書き換えません。注文ステータスを変える新たな操作では、3種類の状態を使います。

更新には注文のバージョンと状態を照合し、同時に発送・編集・キャンセルされても一方だけを成立させます。注文とその監査を同じトランザクションへ保存し、金額・送料・注文時点の単価をステータス変更だけで更新しません。

## 注文画面の改善

必須項目は赤い「必須」で表示します。カート内で配送先を変更した後はカートへ戻り、商品・数量・備考を保持します。違う配送先を選んだ場合は、到着希望日をいったん解除し、新しい配送先の候補と送料を確認してから注文を確定します。同じ配送先を選び直した場合は、選択済みの日付を維持します。

配送先選択を閉じた場合も、カートから開いていればカートへ戻ります。商品をまだ選んでいない状態で注文ページの配送先だけを変えた場合は、商品選択を続けられます。

## 検証範囲

- `tests/order-status.test.ts`：実際のHonoルートとSQLiteで、3状態、過去状態の読取、企業境界、期限・請求・編集ロック、バージョン競合、発送とキャンセルの同時競合を確認します。
- `tests/e2e/order-status.spec.ts`：管理画面の受付・発送・訂正・取消・操作可否を、スマートフォン幅で確認します。
- `tests/e2e/customer-cart-address.spec.ts`：配送先変更後のカート復帰、数量・備考の保持、配送日再選択、送料再見積、必須表示と横はみ出しを確認します。

自動テストはローカル環境で実行します。本番の既存注文を状態変更や取消の試験に使いません。
