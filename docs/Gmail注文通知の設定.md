# Gmailで注文通知を受け取る

管理画面の「設定 → メール」で、新しい注文・注文変更・キャンセルの通知先を設定します。メールアドレスは最大20件、1欄に1件入力します。各通知先へ別々に送信するため、ほかの通知先はメールに記載しません。Gmail以外の受信先も指定できます。

## Gmailを送信元にする

1. オーナー権限の管理者で「設定 → メール」を開き、送信方法に「Gmail（Google連携）」を選びます。
2. 送信に使うGmailアドレスと、注文通知を受け取るアドレスを入力します。送信元には連携するGoogleアカウントのアドレス、またはそのGmailで送信を許可済みのアドレスを指定します。
3. [Google CloudのAPIライブラリ](https://console.cloud.google.com/apis/library/gmail.googleapis.com)で、使用するプロジェクトのGmail APIを有効にします。
4. Google Auth Platformのブランディング・対象・データアクセスを設定します。必要な権限は `https://www.googleapis.com/auth/gmail.send`（メール送信）だけです。受信メールの読み取り権限は使いません。テスト用の外部アプリでは、送信に使うGoogleアカウントをテストユーザーへ登録します。
5. [Google Cloudの認証情報](https://console.cloud.google.com/apis/credentials)で、OAuthクライアントIDを作成します。種類は「ウェブアプリケーション」です。
6. 「承認済みのリダイレクトURI」に、メール設定画面のURIをそのまま登録します。本番では次のURLです。

   `https://kojima-brewery-v2-a6577637.crossover-616.workers.dev/admin/settings/mail/callback`

7. 発行されたクライアントIDとクライアントシークレットをメール設定画面へ入力し、保存します。シークレットはチャットへ送らず、設定画面へ直接入力してください。保存後は再表示しません。空欄で保存すると保存済みの値を維持します。
8. 「Googleで連携」を押し、Googleの画面でメール送信を許可します。元の管理画面に戻り「接続済み」と表示されたら連携完了です。管理者セッションが切れている場合は、同じページで管理者ログインをやり直します。
9. 「テストメールを送る」で通知先を確認して送信し、実際の受信箱を確認します。テスト送信は通常通知をオフにしたまま行えます。確認できたら「メール通知をオンにする」と必要な通知タイミングを保存します。

Googleの外部アプリが「テスト」状態の場合、送信権限の継続利用に使う更新トークンが7日で期限切れになる場合があります。継続運用ではGoogleの公開・審査要件を満たして本番運用向けの公開状態にし、必要に応じて再連携してください。画面に表示されるGoogle側の制限や審査要求に従います。

Gmailの送信元アドレスを入力するだけでは接続されません。Googleのクライアント設定と本人による送信許可が必要です。クライアントIDまたはシークレットを変更すると、以前の連携を解除して再連携を求めます。認可を取り消した場合や途中でページを閉じた場合も、「Googleで連携」から開始し直せます。

## 通知の内容と操作

注文通知には注文番号、到着希望日、金額、取引先・担当者、管理画面の注文詳細リンクを含めます。通知は受注データの保存後に実行し、メールの失敗で注文登録を取り消しません。同じ注文登録リクエストの再実行で新しい注文通知を重複して起動しません。

「動作確認用のテスト注文」は通常のメール通知の対象外です。メールの接続確認には、メール設定内の確認付きテスト送信を使用してください。通常通知をオフにしても、テスト送信を明示した場合は登録済みの宛先へ送信します。

「Googleとの連携を解除」は、このシステムに保存した継続送信用の接続情報を削除し、Gmail通知をオフにします。Googleアカウント側の許可も削除したい場合は、[Googleアカウントの接続済みアプリ](https://myaccount.google.com/connections)から解除してください。

既存のResend設定も送信方法として維持します。この方式ではWorkerの `NOTIFICATION_EMAIL_API_KEY` と `NOTIFICATION_FROM` が必要です。Gmailへ通知を届けるだけなら、送信元をResend、受信先をGmailにする運用もできます。

## 保存と保守

メール設定・連携・テスト送信はオーナー管理者だけが操作できます。専用API `/api/admin/mail-settings` を使い、一般のシステム設定とは別のテーブルへ保存します。migration `0006_email_notifications.sql` の適用が必要です。

クライアントシークレット、更新トークン、一時的なPKCE情報は、`SESSION_SECRET` から用途を分けて導出した鍵でAES-GCM暗号化します。秘密値は設定の取得APIや監査へ返しません。セッション鍵を変更すると保存済みの暗号化情報を復号できなくなるため、通常デプロイでは既存鍵を維持してください。鍵を更新する場合はクライアントシークレットの再保存とGoogleの再連携が必要です。

OAuthの引き継ぎ情報は開始した管理者・クライアント設定・戻り先に結び付け、10分で失効し、一度だけ使えます。Googleから戻った認可コードと状態はURLから除去し、ブラウザーの永続ストレージへ保存しません。通知の監査記録へGoogleの応答本文や秘密情報を保存しません。

開発環境では実際のGmail認可・メール送信を行いません。自動テストはGoogleの応答を模擬します。本番での接続成功と受信成功は、本人のGoogle連携・テストメールの実受信で確認してください。
