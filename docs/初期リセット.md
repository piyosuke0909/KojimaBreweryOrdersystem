# 初期リセット

更新日: 2026-10-23（日本時間）

管理画面の「設定」→「初期リセット」から、引き渡し前の業務データと変更した設定を初期状態へ戻せます。オーナー権限の管理者だけが実行できます。

この機能に取り消し・自動バックアップはありません。必要な注文、帳票、取引先情報などを事前に保存し、使用中の方がいない状態で操作してください。機能の導入や画面を開くだけで、既存のデータが初期化されることはありません。

## 操作手順

1. オーナー管理者でログインし、「設定」→「初期リセット」を開きます。
2. 削除対象の件数と、初期値へ戻す内容・維持する内容を確認します。
3. 現在の管理者パスワードを入力し、「リセット対象を確認」を押します。この段階ではデータを削除しません。
4. 最終確認に表示された件数を確認し、確認欄へ `初期リセット` と入力します。
5. 「確認して初期リセット」を押して実行します。

パスワード確認は5分間有効で、1回の実行にだけ使用できます。確認後に注文や設定などが変更された場合、パスワードを再入力して最新の対象を確認する必要があります。通知やリッチメニュー設定などの処理が進行中の場合も、処理完了後に確認し直してください。

通信エラーになった場合、自動では再実行しません。処理が完了した後に応答だけ届かなかった可能性があるため、まず「リセット対象を読み直す」で現在の状態を確認してください。必要な場合は、パスワード入力からやり直します。

## 削除・初期化する内容

| 対象 | リセット後 |
| --- | --- |
| 取引先、配送先、契約、取引先別単価 | 登録なし |
| LINE担当者と企業の紐付け、招待QR、登録途中の引き継ぎ情報 | 登録なし。保存していた招待QRも使用できなくなります |
| 注文、変更履歴、明細、梱包情報、注文の操作記録 | 登録なし |
| 管理画面で保存したLINEチャット、通知、既読状態 | 登録なし |
| 請求書、請求明細、請求書・納品書の発行履歴 | 登録なし |
| 商品、商品画像、説明、追加した商品 | 標準の11商品を初期価格・内容で登録し直し、すべて「注文不可」 |
| 配送ルール、梱包箱、ヤマトサイズ・運賃、休業日 | 登録なし。通常日は休みなし |
| 会社情報・振込口座 | 会社名・表示名「小島醸造」と初期案内のみ。住所・連絡先・口座などは未登録 |
| 税・注文・配送・梱包・帳票の設定 | 初期値。税率10%、配送リード日数4営業日、変更・取消の締切3営業日前17時、配送・梱包の3機能はオン、固定送料は未設定 |
| メール設定 | 通知オフ。通知先、クライアントID、保存したシークレット・トークン、認可途中の状態を削除 |
| 操作中の管理者以外の管理者 | 削除 |
| 過去の監査ログ | 削除。実行日時・操作した管理者ID・削除件数などの最小限のリセット記録を1件保存 |

商品重量の `0.001kg` は初期化用の仮値です。実測重量を設定し、価格・商品説明・画像・販売状態を確認してから注文を再開してください。配送・梱包の機能がオンでも、ルールや箱・サイズ・運賃は未登録です。実際の配送条件を設定するか、機能をオフにして固定送料または管理者指定の送料を設定してください。

## 維持する内容と、再開時の設定

操作中のオーナー管理者のユーザー名・パスワード・表示名は維持します。操作中のブラウザーには新しいログイン状態を発行し、以前の管理者・注文者のログイン状態は無効にします。同じLINEアカウントを再登録しても、リセット前のログイン状態は復活しません。

CloudflareのWorker・D1・環境変数・Secretと、LINEのチャネル・LIFF・Webhookなどの接続設定は維持します。設定済みのLINEリッチメニューも外部サービス側に残ります。引き渡し先を別のLINE・Cloudflareアカウントに変更する場合は、接続先を別途変更してください。

LINE公式アカウントの友だち、LINEアプリ内のトーク、送信済みメールは、このシステムの初期リセットでは削除しません。Google側のアクセス許可も解除しません。必要な場合はGoogleアカウント側で解除してください。端末にダウンロード済みの帳票やQR画像、外部に保存したデータも各保存先で管理します。

注文再開前に、会社情報・振込先、商品価格と重量、配送・梱包・送料、税・注文期限、帳票、必要に応じてメールを設定します。取引先・配送先を登録し、新しい招待QRでLINE担当者を登録してください。

## 実装と検証の範囲

導入には `0011_system_reset.sql` が必要です。マイグレーションは初期化状態・一時的な実行確認・処理中の情報を保存するテーブルを追加し、既存の業務データを削除しません。

削除と初期値の登録は1つのデータベーストランザクションで行い、途中で失敗した場合は反映しません。古いリクエストからの書き込みを世代で拒否し、外部送信の処理中はリセットを拒否します。パスワードや一時確認トークンの生の値を監査へ保存せず、画面のURLや永続ストレージへも追加しません。

本番データのリセットは、この機能追加の作業としては実行しません。実行成功・初期値・失敗時の保護などの破壊的な検証は、隔離したテスト用データベースで行います。本番の確認は画面表示・認証・件数の取得と、既存データの保持を対象にします。

## 取引先編集の確認位置

取引先情報の編集で「入力内容を確認」を押すと、確認メッセージまでスクロールします。「入力内容を確認しました。下の『確認して保存』を押すと反映されます。」を確認し、最後に「確認して保存」を押してください。最初の確認操作だけでは保存しません。内容を入力し直した場合は、再度確認が必要です。
