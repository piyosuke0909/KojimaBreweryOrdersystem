# LINEメッセージと管理者通知

更新日: 2026-10-22

取引先に登録済みのLINE担当者と、管理画面からテキストでやり取りできます。今回の「メール」はLINEメッセージを指します。Gmailの受信メールを取り込む機能ではありません。

## 取引先とのやり取り

1. 管理画面の「取引先管理」から取引先を開き、「LINEメッセージ」タブを選びます。
2. 担当者を選ぶと、その取引先・担当者の会話を表示します。同名の担当者は登録日時で区別できます。会話がある有効な担当者を優先して並べます。
3. メッセージを入力し、「送信内容を確認」を押します。宛先と本文を確認して送信します。テキストは最大5,000文字です。
4. 過去の会話は追加で読み込めます。通常は直近30件を取得し、会話を開いている間は20秒ごと、画面に戻ったときにも更新します。

取引先やLINE担当者が無効・解除済みの場合、送信はできません。開発環境では実際のLINE送信を停止しています。本番では、既存のLINEチャネル設定とトークン取得処理を利用します。

「送信済」はLINE APIが送信要求を受け付けた状態です。相手の端末への到達や既読を保証する表示ではありません。友だち追加やブロックの状態によって、相手に届かない場合があります。

## 受信する内容

署名を検証したWebhookから、登録済みのLINE利用者IDと完全一致する担当者のメッセージだけを保存します。受信時に担当者や企業の紐づけを新しく作成・変更しません。名前の一致や友だち追加イベントから企業を推測する処理もありません。

テキストは本文を表示します。画像・動画・音声・ファイル・位置情報・スタンプは、受信した種類を表示します。添付内容はこの管理画面へ取得せず、LINE公式管理画面で確認します。Webhookの再配信で会話や通知が重複しないよう、イベントとメッセージの識別子を照合します。

送信取消イベントを受け取った場合、保存済み本文を「送信が取り消されました」に置き換えます。取消が先に届いた場合も、その後の本文保存を抑止します。すでにブラウザーへ読み込んだ古いページの会話は、再読込まで前の表示が残る場合があります。

従来の本人確認用メッセージ `通知確認-` に続く半角英大文字・数字6文字との完全一致は、会話保存と管理者通知の対象外です。従来の診断処理の約束を維持します。

導入前のトーク履歴をLINEから遡って取り込む機能はありません。導入後、Webhookで受け取った対象メッセージから会話を蓄積します。

## ベルと未読件数

右上のベルは新規注文・注文内容の変更・キャンセル・LINE受信を通知し、最新5件を表示します。通知を押すと、該当注文または取引先のLINE会話へ移動できます。ベルの未読件数は全通知の件数で、一覧の5件を超える場合があります。

左メニューの赤い数字は、「注文管理」に注文・変更・キャンセルの未読件数、「取引先管理」にLINE受信の未読件数を表示します。100件以上の数字表示は `99+` です。

未読・既読は管理者ごとにサーバーへ保存します。他の管理者の操作で自分の未読が消えることはありません。ベルを開くだけでは既読にせず、通知のリンクを押したときにその通知を既読にします。「すべて既読」は、その管理者の通知全体が対象です。

LINE会話では、開いた会話に読み込まれた受信メッセージだけを既読にします。別の担当者の会話、まだ読み込んでいない過去の会話、表示した後に新しく届いたメッセージをまとめて既読にはしません。

通知は画面を表示している間は25秒ごと、画面に戻ったときにも更新します。即時配信ではないため、受信から数字が変わるまで時間差があります。既存の注文を導入時に新着として作り直す処理はありません。

## 送信結果が不明なとき

送信ごとにUUIDを発行し、LINEの再試行キーとして利用します。同じ送信への同時操作や通信再試行で、別の送信を増やさない構成です。

通信が切れるなどして結果が確認できない場合は、「送信結果を確認できません」と表示します。新しい送信は一時停止し、まず「送信状況を確認」を利用します。履歴に「同じメッセージを再送」が表示された場合も、元のUUIDと本文を使用して再試行します。LINEの再試行キーの有効期間を考慮し、再試行は作成から23時間以内に限定します。無期限の自動再送は行いません。

送信処理中の要求は一定時間、別の処理から再送できないようにします。API応答だけで成功と決めず、失敗・結果不明・送信中を区別します。本文や生のLINE利用者ID、アクセストークンを送信監査へ記録しません。

## 導入と検証範囲

`0007_admin_notifications.sql` と `0008_line_messages.sql` の適用が必要です。通知は業務データと同じD1バッチへ保存し、既読は管理者別テーブルへ保存します。管理APIは管理者認証、書込時のCSRF対策、取引先と内部担当者IDの照合を利用します。

検証対象は、署名・再配信・未登録利用者の除外・企業境界・送信取消・本文と秘密情報の漏えい防止・重複送信防止・管理者別既読・画面操作です。外部のLINE APIを模擬するテストを含みます。この追加機能について、実端末からの新規受信と管理画面からの返信到達は別途確認が必要です。過去の登録通知・注文通知の端末到達確認と区別します。
