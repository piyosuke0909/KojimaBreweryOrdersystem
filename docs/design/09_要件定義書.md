# 小島醸造 LINE法人受注システム 要件定義書

作成日: 2026-10-19  
版: 2.0（TypeScript + Hono + Cloudflare D1 対応版）  
対象システム: 小島醸造 法人向けLINE受注システム

---

## 1. 文書目的

本書は、小島醸造が法人取引先から受け付ける酒類注文を、LINE公式アカウント・LIFF・**TypeScript + Hono（Cloudflare Workers）**・**Cloudflare D1** 等を用いて電子化するための要件を定義する。

現在は法人取引先からの注文を主に電話で受け付けており、注文受付、確認、転記、取引先ごとの価格確認等に手間がかかっている。

本システムでは、法人取引先がLINEだけで簡単に注文を完結でき、小島醸造側は管理ポータルから取引先・招待QRコード・取引先別販売単価・商品・注文・配送・請求・帳票プレビュー＆PDF出力・各種設定を一元管理できる状態を目指す。

---

## 2. システムの目的

- 法人取引先からの電話注文を減らし、LINE上で注文〜履歴確認〜変更・キャンセルを完結できるようにする。
- **企業ごと（取引先ごと）・商品ごとに設定された販売単価（定価）**を正しく表示・適用する。
- 企業IDを紐づけた招待QRコードを発行し、`QR読み取り → LINEログイン → 友だち追加 → リッチメニュー → 注文` のスムーズな導線で、LINEユーザーIDと取引先企業を確実に紐付ける。
- 小島醸造側の受注確認・配送手配・納品書および請求書作成業務を簡素化する。
- 高齢者やITに詳しくないスタッフでも迷わず操作できる管理画面を提供する。
- 将来の価格、消費税、会社情報、銀行口座、問い合わせ先、配送料等の変更を、コード修正なしで管理者が行えるようにする（宅急便の配送会社はヤマト運輸を使用する）。
- 有料ストレージ等のランニングコストを抑え、Cloudflareの無料枠を中心に安定稼働・保守できる構成とする。

---

## 3. 対象利用者

### 3.1 法人取引先（顧客）
本システムは法人取引先専用とする。
- 酒店、ホテル、飲食店、バー、土産店、製菓事業者、その他小島醸造と契約のある法人・店舗の発注担当者（1企業につき複数名の担当者を登録可能）。

### 3.2 管理者（小島醸造）
- 経営者、従業員、アルバイト、受注・配送担当者。
- ITに詳しくない利用者や高齢者でも直感的に操作可能なUIとする。

## 4. システム構成

### 4.1 顧客側
- LINE公式アカウント & LINEリッチメニュー
- LIFF Web App（React + Vite + Tailwind CSS）
- LINE Login（友だち追加オプション連動）& LINE Messaging API
- Hono API（Cloudflare Workers）

### 4.2 管理者側
- 管理者ポータル Web App（React + Vite + Tailwind CSS）
- 帳票プレビュー＆PDFダウンロード機能（納品書・御請求書・QR招待案内状）
- 通知用Gmail連携

### 4.3 データ保存（Cloudflare D1）
- **Cloudflare D1（SQLite + Drizzle ORM）** をデータベースとして利用する。
- 課金要因となる外部オブジェクトストレージ（Cloudflare R2等）は使用せず、発行済み請求書等の帳票データはD1内にJSONスナップショットとして保存し、いつでも管理画面上でプレビュー表示およびPDFダウンロード・印刷を行える構成とする。

## 5. LINEリッチメニュー要件

LINE公式アカウントのリッチメニューは以下の4項目とする。

| 項目 | 遷移先 | 機能 |
|---|---|---|
| **注文** | `/order` | 配送先確認、商品選択、数量変更、カート確認、到着希望日指定、注文確定 |
| **注文履歴** | `/orders` | 過去・現在の注文一覧、注文詳細、注文直接編集、キャンセル |
| **お問い合わせ** | `/contact` | 電話番号、メールアドレス、受付時間の表示 |
| **商品紹介** | `/products` | 商品画像、商品名、容量、4枠詳細（説明・こだわり・味わい・飲み方）の閲覧 |

## 6. 初回登録・QRコード取引先識別要件（企業単位・複数人対応）

### 6.1 企業別QRコード招待方式
初回登録は、利用者に取引先コード等を手入力させる方式ではなく、**管理者が取引先企業に紐づけて発行する招待QRコード（および招待URL）方式**とする。

- 管理者は管理ポータル（`A-08`）上で対象取引先を選択し、招待QRコードを発行する。
- 発行したQRコードは、案内状として画面プレビュー（`A-24`）からPDFダウンロードまたは印刷して取引先へ配布できる。
- URLには取引先ID等の内部情報を直接含めず、推測困難なランダムトークンを使用する（例：`https://.../invite?t=<ランダムトークン>`）。

### 6.2 招待QRコードの要件（同一企業の複数スタッフ登録対応）
- **企業単位で複数人が読み取れる仕様**: 1つの招待QRコードに対して**最大登録可能人数（`max_uses`、初期値：5名、無制限も設定可）**と**有効期限（`expires_at`、初期値：30日間）**を持たせ、同一企業の複数スタッフ（店長、発注係など）が同じQRコードを読み取って登録できるようにする。
- D1には生トークンではなくSHA-256ハッシュ値を保存する。
- 管理画面からいつでも「上限人数・有効期限の変更」「即時無効化」「新しいQRコードの再発行」を行える。
- 発行日時、現在登録済み人数、登録した各担当者の氏名・LINE表示名・登録日時を記録し、管理画面で確認・個別解除できる。

### 6.3 LINEログイン・友だち追加・企業紐付けフロー
1. 招待QRコードを読み取った利用者は **LINE Login** を行う（`bot_prompt=aggressive` により同時に**LINE公式アカウントの友だち追加**を促す）。
2. Hono API側でLINE ID Tokenを検証し、`lineUserId` を取得する。
3. 招待トークンの有効性（有効期限内かつ登録人数上限未満）を確認し、`L-01 招待登録` 画面に取引先企業名を表示する。
4. 利用者が**「ご担当者名（例：山田 太郎）」**を入力して `[登録する]` を押すと、`LINE userId ↔ 取引先ID` を紐付けて `line_users` テーブルに保存し、QRコードの使用回数を `+1` する。
5. LINE Messaging APIでトーク画面へ登録完了メッセージを自動送信する。
6. 2回目以降は、リッチメニューからLIFFを開いた際に `lineUserId` から取引先企業を自動判定する。

### 6.4 誤紐付け防止と再読み取り時の挙動
- **同一企業への登録済みユーザー**: すでに同じ取引先に登録済みの `lineUserId` が再度同じQRコードを読み取った場合は、枠を消費せず注文画面（`L-03`）へ案内する。
- **別企業への登録済みユーザー**: すでにA社に紐付いている `lineUserId` がB社の招待QRコードを読み取っても、自動で所属変更せずエラー画面（`L-18`）を表示する。所属変更が必要な場合は管理者による紐付け解除を必要とする。

## 8. 契約・取引先別販売単価（企業別定価）要件

### 8.1 契約管理
- 取引先ごとに契約（契約ID、取引先ID、契約名、開始日、終了日、締日、支払条件、状態、備考）を管理する。支払方法は掛売りとする。

### 8.2 取引先別販売単価
- 商品の販売単価は一律ではなく、**取引先ごと・商品ごとに税抜の販売単価を設定**できる（`company_product_prices`）。
- 同一商品であっても、A酒店（2,100円）・Bホテル（2,300円）・C飲食店（2,500円）のように企業ごとに異なる販売単価を設定可能とする。
- 注文数量に応じた自動値引きは行わない。
- 取引先別販売単価が未設定の商品は、商品マスタの `標準卸価格` を適用する。ただし `業者限定` フラグがONの商品は、取引先別販売単価で取扱可（`is_available = 1`）と設定された取引先にのみ表示・販売する。

### 8.3 価格履歴と注文時単価の維持
- 取引先別販売単価を改定する場合は、適用開始日・適用終了日を用いて履歴を保持する。
- **過去注文および同一注文内の単価維持**:
  - 注文確定時に `order_items.unit_price` へ注文時単価をスナップショット保存する。
  - 注文編集（数量変更）を行う場合も、**同一注文内の既存商品は初回注文時の単価をそのまま維持**する（新規追加した別商品のみ編集時点の単価を適用する）。

## 9. 注文画面・カート要件

### 9.1 注文商品一覧（`L-03`）
- スマートフォン縦画面・白基調＋紺/金アクセントのカード形式で表示する。
- 各カードに商品画像、商品名、商品区分、容量、短い説明、**自社専用の適用販売単価（税抜）**、数量変更ボタン（`[-]` `[+]`）を表示する。
- 画面上部に現在選択中の配送先を表示し、`[変更]` から複数配送先（`L-04`）を切り替え可能とする。
- 画面下部に固定カートバー（選択商品数、合計本数、商品小計、`[カートを見る]` ボタン）を表示する。

### 9.2 カート Bottom Sheet（`L-05`）
- 商品明細（数量変更・削除可）、商品小計（税抜）、配送先、配送方法、配送会社（ヤマト運輸 / 自社便）、梱包予定（個口数・サイズ）、配送料、消費税、税込合計、到着希望日選択ボタン、注文確認ボタンを表示する。

## 10. 配送・梱包・送料要件

### 10.1 初期配送ルール
1. **指定地域配達（自社便・送料無料）**: 犬山市、小牧市、丹羽郡、江南市、各務原市、可児市。配送可能期間：毎月1日〜7日、15日〜22日。
2. **45km圏内配達（自社便・送料無料）**: 小島醸造から45km以内の地域。配送可能期間：毎月1日〜7日。
3. **宅急便配送（ヤマト運輸固定・送料加算）**: 上記以外の地域。商品重量と梱包箱マスタ・ヤマトサイズマスタ・ヤマト運賃マスタから個口数と配送料を自動計算する。

### 10.2 配送カレンダーと到着希望日
- 管理者が配送可能日・不可日（定休日、イベント出店、休業日、その他）を設定できる（`A-12`）。
- 新規注文時は「最短リードタイム（初期値：4営業日後以降）」かつ「配送ルール期間内」かつ「配送カレンダー可能日」のみ選択可能とする。

## 11. 税・金額計算要件

- **価格区分**: 税抜で統一管理する。
- **消費税率**: 管理者設定可能（初期値：`10%`）。
- **税計算単位**: `請求単位` / `注文単位` / `明細単位` から選択可能（初期値：`請求単位`）。請求単位の場合、注文画面の消費税は「参考税額」と明示し、請求書発行時に正式税額を計算する。
- **端数処理**: `切り捨て` / `切り上げ` / `四捨五入` から選択可能（初期値：`切り捨て`）。

---

## 12. 注文変更・キャンセル・ロック要件

- **変更・キャンセル期限**: **到着希望日の3営業日前 17:00まで**。
- **ステータス条件**: 全6ステータス（`受付済` / `確認済` / `配送準備中` / `発送済` / `完了` / `キャンセル済`）のうち、顧客が編集・キャンセル可能なのは **`受付済` または `確認済`** のみ。
- **注文編集ロック**: 同時編集を防ぐため、編集開始時に10分間のロックを取得し、保存時に `version` 番号で楽観ロック検証を行う。
- **変更履歴保存**: 変更前後の明細JSONと合計金額を改訂番号（`rev.1`, `rev.2`...）付きで `order_revisions` に保存する。
- **請求書発行後の注文ロック**: 請求書発行済みの注文（`is_invoice_locked = 1`）は編集・キャンセル不可とする。修正時は `請求取消 → ロック解除 → 注文修正 → 請求書再発行` の手順とする。

## 13. 帳票プレビュー・PDFダウンロード要件（納品書・請求書・QR案内状）

Cloudflare R2等の外部有料ストレージを使用せず、管理ポータル内の **帳票プレビュー画面（`A-24`）** でA4印刷レイアウトを表示し、ワンクリックで **PDFダウンロード** または **印刷** ができるものとする。

### 13.1 納品書
- 出力項目：納品書タイトル、発行日、注文番号、宛先（取引先・配送先）、小島醸造の会社情報・登録番号・担当者、商品明細（商品名・容量・数量・単位・単価・金額）、商品小計、配送料、消費税額、税込合計金額、備考。

### 13.2 御請求書
- 契約の締日に基づき対象注文を集計して発行する。
- 出力項目：御請求書タイトル、請求書番号、請求日、支払期日、宛先、ご請求金額（税込）、小島醸造の会社情報、適格請求書発行事業者登録番号、**振込先銀行口座情報（銀行名・支店名・普通/当座・口座番号7桁・口座名義）**、対象注文明細、税抜小計、消費税額、税込合計、備考。
- 発行時点の全印字データを `invoice_histories.snapshot_json` に保存し、過去発行分（第1版、第2版...）もいつでも当時と同一内容でプレビューおよびPDFダウンロードができる。

### 13.3 QRコード招待案内状
- 取引先へ手渡し・送付するための案内状（取引先名、招待QRコード、登録手順説明、有効期限）をA4プレビュー＆PDFダウンロード・印刷できる。

## 14. 通知・監査ログ・非機能要件

- **通知**:
  - 新規注文・注文編集・キャンセル時に小島醸造の通知先Gmailへメール通知する。
  - 初回登録完了・注文確定・キャンセル時に、取引先担当者のLINEへMessaging APIで通知メッセージを送信する。
- **監査ログ**: 主要操作（マスタ変更、単価変更、注文操作、請求操作、QR招待操作）を操作者ID・変更前後JSONとともに `audit_logs` へ記録する。
- **酒税の分離**: 酒税を注文時の別明細として加算しない。酒税帳簿・申告管理は本受注システムのMVP対象外とする。
